# QwenPaw上下文压缩改良

一个 QwenPaw 插件：把上下文压缩时「摘要怎么生成」这一步整个换掉。装上即生效，无需任何配置，其余压缩管线一行不动。

## 如何使用

**装上即生效，无需任何操作。** 之后发生的每一次上下文压缩——长会话自动触发、`/compact` 命令、模型主动调用压缩工具——都走改良管线（当前默认 `replace` 模式，全量替换原版摘要生成）。效果直接体现在压缩后的新上下文里：摘要变为五章节中文格式，末尾附带压缩完成时间与找回原文的即用指令；随时用 `/compact_str` 查看当前摘要。`replace` 模式下无需再输入 `/compact new`——该触发词仅供 `shadow` 调试模式使用。

如果你在用 QwenPaw（2.3.0+）的长会话，大概率遇到过这些情况：压缩之后新会话的摘要答非所问、关键细节丢失、中文摘要偶尔生成失败导致上下文被照常驱逐、或者压缩时明显卡顿很久。这个插件就是冲着这些问题来的。

## QwenPaw 原版上下文压缩的问题

QwenPaw 在上下文过长时会自动压缩历史对话，生成一份摘要替换原始内容。这套机制里，「摘要怎么生成」的实现方式有几个先天缺陷：

| 问题 | 原版的做法 | 你会感受到什么 |
|------|-----------|----------------|
| **模型看不到真实对话** | 把要驱逐的内容压成一份扁平文本 dump，还带各种截断（用户消息 ≤8000 字符、助手消息 ≤2000、工具结果 ≤600 字符预览、整体 80K 上限） | 摘要只能「转述转述再转述」，细节层层丢失，越长的会话摘要越空 |
| **零缓存复用** | 摘要请求是独立构造的「指令 + 证据 dump」，与主对话的请求前缀毫无重叠 | 压缩时模型要把几十万 token 从头重新算一遍（KV cache 完全用不上），又慢又贵 |
| **校验过严** | 三层机械检查：标题逐字按序、标题外不许有任何文本、identifier 幻觉检查、secret 扫描……格式稍微漂移就判定失败 | 中文场景下格式漂移很常见，重试预算白白烧掉，最后摘要生成不出来 |
| **重试看不到上一稿正文** | 失败后重新生成（只有 1+1 两次机会），模型只收到一份校验失败问题清单，看不到自己上一稿写了什么 | 重试几乎等于从头再来，同样的问题容易再犯 |
| **失败静默驱逐** | 摘要生成失败时静默降级，然后照常驱逐原始上下文 | 最危险的一条：摘要没生成好，原文照样被驱逐出上下文——原始数据仍在 history.db 可间接找回，但对话现场已经没了 |

## 这个插件做了什么

只替换压缩管线的第 5 步（摘要生成），其余 8 步与基础设施全部继承。核心改良：

**1. 让模型读真实对话，而不是啃 dump**

摘要请求 = 当前完整上下文 + 一条追加提问。模型看到的就是真实对话本身，然后以「续写」的方式写出摘要——user/assistant 原文都在，不用经过一层有损转述。

**2. 逐字节对齐 prefix cache，压缩不再「从头算」**

摘要请求与主对话请求逐字节同前缀（同一套代码构造、tools 保留 + `ToolChoice(mode="none")`）。KV cache 直接复用，只新算「提问 + 摘要输出」。在支持缓存的 provider（如火山方舟 GLM）上实测：重试时前缀 84K token 全量命中，压缩耗时几乎全是纯生成。

**3. 校验只查要点，中文友好**

只查 5 个必备章节标题是否存在（允许尾随冒号），不再有逐字节格式审查：

```markdown
## 当前任务
## 当前状态
## 约束
## 决定
## 待办
```

**4. 重试是「对话内纠正」，模型看着自己的上一稿补**

失败时把上一稿和缺失章节清单一起发回对话里，模型只补缺的部分——不是失忆重来。共 4 次尝试。实测中一次「撞 max_tokens 截断」的失败稿在重试时被完整救回，且因为前缀缓存命中，重试几乎没有额外开销。

**5. 失败绝不静默驱逐上下文**

摘要生成失败 = 压缩中止 + 错误上浮，原始上下文原封不动。宁可让这一轮对话失败，也不丢历史。（搭配 keep-context-after-compact-failure 插件可获得更友好的失败提示，两者兼容。）

**6. 摘要末尾自带「怎么找回原文」的指引（v0.2.1）**

每份摘要末尾固化追加一段即用指令（下为一次真机压缩的示例，时间与 seq 区间随每次压缩变化）：

```markdown
---
上下文压缩已完成。当前时间：2026-11-18 21:45:29 +08:00

📎 查看压缩前原始上下文（本摘要覆盖 seq 167415–170642）：
- 读原始轮次全文：recall_history(op="expand", lo=167415, hi=170642)
- 按关键词搜索：recall_history(op="search", query="<关键词>", k=20)
- 折叠的工具结果按 [scroll folded] 标注的 tool_call_id 召回：
  recall_history(op="recall_tool", tool_call_id="<id>")
```

时间是压缩发生时刻（当地时间 + UTC 偏移），seq 区间与上一段摘要无缝衔接。

**7. 按模式精准补强**

- `/compact`、压缩工具、自动压缩：全链路走新方案（当前默认 `replace` 模式）
- 无 agent 场景的 `/compact_str`：原版对结构化摘要本就正常显示；本插件把摘要换成自由文本类型后原渲染路径无法识别，因此补一处兼容 patch 让新摘要同样正常显示
- `/compact new`：仅在 `shadow` 调试模式下注册（新旧管线一次性对照入口）；默认 `replace` 模式下不安装此拦截，`/compact new` 保持宿主原生行为

各点位独立降级——某个辅助点位失效只影响对应入口，不阻塞压缩主体。卸载时宿主代码逆序完整恢复原状；但卸载前已生成的自由文本摘要，宿主原版无法读取——旧会话恢复后摘要将不可用（归档索引与 recall 不受影响）。卸载前如需保留摘要文本，请先在会话中查看并复制。

## 一览对比

| 维度 | QwenPaw 原版 | 本插件 |
|------|-------------|--------|
| 摘要输入 | 有损 dump（多层截断） | 全量真实对话 |
| prefix cache | 不复用 | 逐字节对齐，KV cache 全量复用 |
| 摘要语言/结构 | 英文标题 + 严格结构（zh 配置下正文中文） | 固定五章节中文摘要 |
| 校验 | 三层机械检查 | 只查章节标题存在 |
| 重试 | 带问题清单重试 1+1 次（无上一稿正文） | 对话内纠正（含上一稿），共 4 次 |
| 失败语义 | 静默降级 + 继续驱逐 | 中止压缩 + 上浮错误，上下文无损 |
| 摘要末端 | 无 | 压缩完成时间 + recall 即用指令 |
| `/compact_str` | 正常显示（原版结构化摘要） | 正常显示（自由文本摘要经兼容 patch） |

## 需要知道的取舍

这些是作者明确拍板接受的设计代价，如实告知：

- **失败显式化**：自动压缩时摘要持续失败，当前回合会一直失败（上下文无损、不会被驱逐），直到摘要成功为止。这是「宁可失败也不丢数据」的代价。
- **超预算不降级**：tokens 逼近模型上限时压缩会持续失败——故意不设计降级路径（降级=回到有损 dump 老路）。缓解入口已预留。
- **早期工具输出走指针**：更早轮次的工具结果在压缩输入中是一行 `[scroll folded]` 占位符（这是缓存对齐的必要条件），细节通过占位符里的 recall 指令找回。
- **失败后模型可能重调压缩工具**：模型主动调压缩工具失败时可能立刻重试（插件在失败消息中已加「勿重试」指引，宿主自带回合上限兜底），极端情况下仍可能产生较多额外模型调用。
- **摘要恒为中文**：所有语言配置下都产出中文摘要，有意行为。

## 安装

```powershell
qwenpaw plugin install <zip> --force
```

要求 QwenPaw 2.3.0+。安装后自动激活，无需配置——下一次压缩（自动或 `/compact`）就生效。

## 配置（可选）

所有配置默认值开箱即用。配置入口 = **宿主 settings**（`config.plugins.qwenpaw-plugin-context-compactor-refined`，平铺键或 `compactor` 嵌套段均可，若两者同时配置以嵌套段为准）：

| 键 | 默认 | 说明 |
|----|------|------|
| `mode` | `replace` | 另一取值 `shadow` = 调试用透传模式（默认透传原版，仅 `/compact new` 触发新管线并注册其拦截；v0.2.2 起 `replace` 下不再注册该拦截） |
| `sections` | 当前任务/当前状态/约束/决定/待办 | 必备章节 |
| `max_retries` | 3 | 重试上限（首次 1 + 重试 3 = 4 次尝试） |
| `output_tokens` | 0 | 0 = 按宿主公式自动推导 |
| `disable_thinking` | true | 禁思考 |
| `cache_mode` | `preserve_tools` | `no_tools` = provider 不支持 `tool_choice="none"` 时降级 |
| `debug_dump` | false | 排查缓存对齐用：把发给 provider 的原始请求字节 dump 到本地文件做比对 |
| `question_template` / `retry_template` | 见 `prompts.py` | 提问与重试纠正模板的自定义覆盖（一般无需修改） |

> 注：plugin.json 里的 `config` 声明（`debug_dump: false`）在宿主 2.3.0 中**不被消费**，仅为占位——实际生效的是上表的代码默认值，运行时修改请走宿主 settings。
